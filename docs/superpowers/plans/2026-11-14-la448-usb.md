# LA448 over USB Implementation Plan

> **Executed 2026-11-14.** Two things changed after the final review and are recorded in the spec: requests longer
> than one report are refused rather than split (so Task 1's splitting test and Task 4 step 4 no longer apply),
> and units are also matched on the `AudioSystem` product string.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accept `usb` / `usb:<serial>` wherever an IP address is accepted, so an LA448 on USB HID is driven by the existing client, CLI and UI.

**Architecture:** Every caller already reaches the device through `Client(ip)` -> `Transport(ip, port)`, and `Transport` only uses four socket methods (`sendto`, `recvfrom`, `settimeout`, `close`). A new `usb.py` provides `HidLink`, a socket-shaped adapter over one HID device; `Transport.__init__` picks it when the address is a USB address. Pacing, matching, quarantine and keepalive are untouched and shared.

**Tech Stack:** Python 3.12, `hidapi` (import name `hid`) as an optional extra, pytest, mypy strict, ruff.

**Spec:** `docs/superpowers/specs/2026-11-14-la448-usb-design.md`

## Global Constraints

- VID `0x0483`, PID `0x5750`; reports are exactly 64 bytes, no report ID (hidapi writes take a leading `0x00`).
- A frame is zero-padded to a multiple of 64 bytes and sent as consecutive reports.
- Base install stays dependency-free: `hid` is imported only inside the function that opens a device.
- UDP behaviour unchanged; the existing test suite passes unmodified.
- No frame is sent to hardware that the UDP path would refuse. No speculative writes.
- Commits happen only when the user asks; skip the commit steps otherwise.

## Review Focus

- No LA448 plugged in: `ConnectionError("no LA448 found on USB ...")`, not a hidapi traceback. (Task 1)
- Two units plugged in and bare `usb` given: `ConnectionError` listing both serials and the `usb:<serial>` form. (Task 1)
- `hidapi` not installed: `RuntimeError` naming `uv sync --extra usb`. (Task 1)
- Unit unplugged mid-session: `recvfrom` raises `OSError`, so the recv loop reports the link down exactly as it does for a closed socket. (Task 1)
- A hostname that merely starts with "usb" (`usbhost.local`) is still resolved as a network host; `USB` and `usb:` with an empty serial behave as `usb`. (Tasks 1, 2)

### Task 1: `HidLink` and USB address parsing

**Files:**
- Create: `src/sinbosen_la548/usb.py`
- Test: `tests/test_usb.py`
- Modify: `pyproject.toml` (extra `usb = ["hidapi>=0.14"]`; mypy override `module = ["hid"]`, `ignore_missing_imports = true`)

**Interfaces (produces):**
- `VENDOR_ID = 0x0483`, `PRODUCT_ID = 0x5750`, `REPORT_SIZE = 64`
- `parse_address(address: str) -> tuple[bool, str | None]` - `(is_usb, serial)`. USB only for `usb` or `usb:<serial>` (scheme case-insensitive, surrounding whitespace ignored); empty serial -> `None`.
- `list_devices() -> list[str]` - serial numbers of attached units.
- `open_link(address: str) -> HidLink` - resolves the serial, opens the device.
- `class HidLink(device: Any, address: str)` with `sendto(data: bytes, addr: object) -> int`, `recvfrom(bufsize: int) -> tuple[bytes, tuple[str, int]]`, `settimeout(seconds: float) -> None`, `close() -> None`. `recvfrom` returns one report and `(address, 0)`; raises `TimeoutError` when no report arrives within the timeout, `OSError` on a device error.

`_import_hid()` is the one place `hid` is imported; tests monkeypatch it with a fake module exposing `enumerate(vid, pid)` and `device()`.
